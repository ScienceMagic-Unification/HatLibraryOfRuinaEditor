## 0. 目标（已按用户澄清更新）

新增一个**只读**的「奇点」大工作区，整体位于内置资源文件夹内，不对 Mod 做任何修改。它向右连线到三个子工作区：

1. 内置图片（按图片类型分选项卡，只读）
2. 原版正则（只读查看，读取内置 XML）
3. 奇点正则（只读查看，读取内置 XML）

关键澄清（务必遵守）：

- `[X]` 变黄 + 小空格是**原游戏的正则**，**无论是否开启奇点都始终生效**。它不是被奇点切换的“原版正则”。
- `原版正则` 与 `奇点正则` 是两套**关键词/效果文本词典**（见下方 XML 结构），需要先读取并只读显示。
- 两套文件目前是**中文版本**；需要本地化按钮（CN/EN/JP）切换，并联动其余本地化。
- 只读查看工作区要做成**可编辑模板**（带输入框/按钮），在本工作区锁定，未来可在其它工作区正常输入（暂未出现）。
- 内置图片选项卡先做 **射程 / 骰子 / 章节 / 其他** 四个，其余后续再具体开发；图片同样只能查看、不能修改。
- **未选择 Mod 时，奇点不可用**（界面仍要求先选 Mod）。

## 2. 两套正则 XML 的真实结构（重要）

用户提供的两个源文件（中文版，目前位于用户磁盘，不在本仓库内）：

- 原版正则：`D:/制作/XML可视化/Xml/HatKeyword_OriginKeyword.xml`
- 奇点正则：`D:/制作/XML可视化/Xml/HatSingularity_EffectTexts.xml`

两者根节点一致：

```xml
<BattleEffectTextRootExtra>
  <extraTextList>
    <BattleEffectTextExtra ID="...">
      <Name>显示名</Name>
      <RecognizeName>识别名</RecognizeName>
      <Desc>描述，可含 (~HatKeyword id="XXX"/~) 内联引用</Desc>
      <KeywordIconId>图标ID</KeywordIconId>
      <Color>#RRGGBB</Color>
      <HasBracket>true</HasBracket>
      <IsUnderline>true</IsUnderline>
      <IsItalic>true</IsItalic>
      <IsBold>true</IsBold>
      <IsChangeSelf>true</IsChangeSelf>
      <IsChangeAbility>true</IsChangeAbility>
      <IsChangePassive>true</IsChangePassive>
      <IsAutoLink>true</IsAutoLink>
      <IsCardPreview>true</IsCardPreview>
      <CardPreview>602020</CardPreview>   <!-- 可多条 -->
    </BattleEffectTextExtra>
  </extraTextList>
</BattleEffectTextRootExtra>
```

字段说明（新窗口实现读取时以此为准）：

- `ID`（属性）：唯一标识，被内联引用用。
- `Name`：显示名。
- `RecognizeName`：文本中识别该关键词时使用的名字。
- `Desc`：描述；其中的 `(~HatKeyword id="XXX"/~)` 是**内联引用 token**，要解析成对应 ID 条目的文本/颜色/下划线/图标等。
- `KeywordIconId`：图标 ID（对应内置图标）。
- `Color`：命中文本的显示颜色。
- `HasBracket` / `IsUnderline`：是否加括号 / 下划线。
- `IsItalic` / `IsBold`：是否斜体 / 粗体（默认 false）。
- `IsChangeSelf` / `IsChangeAbility` / `IsChangePassive`：作用于 自身 / 能力 / 被动 的范围标记。
- `IsAutoLink`：是否自动链接到其它关键词。
- `IsCardPreview` + `CardPreview`（可多条）：卡牌预览升级相关（指定某些卡牌 ID 在预览中的特殊处理）。

> 待新窗口与用户确认：`原版正则` 与 `奇点正则` 的具体生效时机/组合规则、内联 token 的精确渲染规则、以及 EN/JP 版本文件的放置位置（是否同目录 `_cn/_en/_jp` 后缀，还是子目录）。

## 3. 设计决策

### 3.1 三个子工作区的模块形态

- 给 `ModuleDefinition` 增加可选字段：
  - `readonly?: true`（只读，禁用保存/新增/删除/编辑）
  - `builtin?: true`（内置，任何时候都注册，但受 `modPath` 是否存在的门控）
  - `builtinImages?: { tabId: string }`（内置图片，走只读图库）
  - `builtinRegex?: { setId: 'vanilla' | 'singularity' }`（只读正则查看器，带锁定输入框/按钮的模板）
- 三个子工作区在 `scanMod()` 末尾追加，但**当未选择 Mod（`modPath` 为空）时不显示/不可进入**，符合“未选 Mod 不可用奇点”。

### 3.2 内置资源文件夹结构（提案）

项目根 `内置资源/` 整理为：

```
内置资源/
  图片/
    射程/ Range_*.png
    骰子/ Dice_*.png
    章节/ Icon_Ch*.png
    其他/ （暂空，后续再放）
  正则/
    原版正则_cn.xml
    奇点正则_cn.xml
    （预留 _en / _jp）
```

打包镜像 `apps/desktop/src/renderer/src/assets/` 同步为 `images/{range,dice,chapter,other}/` 与 `regex/`，并更新 `lib/rangeIcons.ts`、`lib/diceIcons.ts` 的 glob 路径。

> 待确认：图标里还有大量 `Hat_*.png` 等关键字图标，最终应归入哪个选项卡（建议归入 `其他` 或新增「关键词图标」选项卡，由用户后续指示）。

### 3.3 内置图片选项卡

- 选项卡：`射程`、`骰子`、`章节`、`奇点`、`原版`、`其他`（名称直接用对应语言的描述，走 i18n）。
- 每页只读平铺展示缩略图 + 文件名，**无**导入/删除/重命名按钮。
- 不要复用现有 `ImageWorkspace`（它是可编辑资源库），写新的只读图库组件。

### 3.4 只读正则查看器（可编辑模板）

- 对 `原版正则` / `奇点正则` 两套 XML，做一个**字段表单模板**：ID、Name、RecognizeName、Desc、KeywordIconId、Color、HasBracket、IsUnderline、IsChangeSelf/Ability/Passive、IsAutoLink、IsCardPreview、CardPreview（多条）。
- 本工作区内这些输入框/按钮全部 **disabled（锁定）**。
- 组件设计成可复用：未来其它工作区传入“可编辑”标志即可正常输入（例如 `readonly={false}`）。
- 需要一个本地化下拉（CN/EN/JP）切换读取哪套语言文件，并影响其余本地化显示。

### 3.5 预览替换引擎（核心，但具体规则待确认）

- 基础：`[X]` → 黄色 + 小空格，**始终生效**（把现有 `AbilityText` 的硬编码保留为“基础规则”，不要删）。
- 升级：读取上述两套 XML，解析为“关键词/效果词典”：
  - 文本中出现 `(~HatKeyword id="XXX"/~)` 或与 `RecognizeName` 匹配的词，按该条目 `Color/HasBracket/IsUnderline/KeywordIconId` 渲染，并按 `IsAutoLink` 自动链接。
  - `原版正则` 始终生效；`奇点正则` 在开启帽子奇点时额外生效并升级预览（具体组合规则待用户告知）。
- 接入点：`PreviewPanel.tsx`（卡牌能力 + 骰子能力 + 前缀行）、`AbilityDescPreview.tsx`、`ProofPanel.tsx`（校对预览）。
- 建议把“当前生效规则集”做成 `usePreviewRules()`（读 `hatEnabled` + 当前正则语言 + 两套 XML），预览组件统一调用。

## 8. 优先级与拆窗口建议
优先级：A（资源整理）→ B（模块+连线+门控）→ D（读取+只读查看器）→ C（图片选项卡）→ E（预览引擎，待规则）→ F（i18n+回归打包）。

- E 依赖用户给出具体正则规则，先搭好框架、不要臆造规则。
- 新窗口只读本文件与 `docs/移交说明.md`，遵守“共享文件只按既有模式扩展、不重构”。
